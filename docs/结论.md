## 二、关键设计决策

这些是**取舍的记录**，比实现细节更值得保留。

### 2.1 架构分层

| # | 决策 | 理由 |
|---|---|---|
| D1 | **前端零构建**：纯 HTML/CSS/JS + `go:embed`，不引入 npm / xterm.js / Monaco 构建链 | 单文件交付、零依赖；xterm/Monaco 列为后续增强 |
| D2 | **文件编辑采用「读 → 旧串替换 → 写」**（同 Claude Code Edit），自动生成 Unified Diff 推送前端；不解析外部 patch 文件 | 比增量补丁应用更稳健，Diff 仅用于展示 |
| D3 | **终端为异步命令执行 + 流式回传**（`exec.Command`），交互式 PTY/ConPTY 列为后续增强 | 非交互执行已覆盖 95% 场景，且纯 Go 无 CGO |
| D4 | **LLM 适配不引入 SDK**，原生 `net/http` + SSE 解析 | 控制依赖与内存占用 |
| D5 | **`custom` = OpenAI 兼容端点**（Ollama / vLLM 均兼容） | 本地模型普遍提供 OpenAI 兼容接口 |
| D6 | **依赖最小化**：websocket / yaml.v3 / wazero / x/sys（全部纯 Go） | 满足 `CGO_ENABLED=0` |
| D7 | **认证**：启动时生成随机 Token，经 HttpOnly Cookie 下发，API 与 WebSocket 都校验 | 本地服务安全闭环 |
| D8 | **MCP 驱动**：单飞行串行 JSON-RPC，`initialize → tools/list → tools/call` | 兼容官方 MCP 规范 |
| D9 | **WASM ABI**：`alloc(i32)→i32`、`manifest()→i64`、`call(ptr,len)→i64`（高 32 位=长度，低 32 位=偏移） | wazero 纯 Go 沙盒约定 |
| D10 | **检索为纯 Go 目录遍历 + 逐行扫描**（跳过 `.git`/`node_modules`/`dist`/`vendor`） | 不依赖 ripgrep 二进制 |

### 2.2 分层落地三条既定决策

来自 `AGENTS.md` §5，**改之前先看，别重新讨论**：

1. **`pathLocks` 留在 Guard，不下沉 Backend。** 锁序是 `pathLock → Guard.mu`（`casWrite` 持路径锁期间要取 `mu` 读 `readSeen`）。跨对象无法表达这个顺序 —— 接口层没有机制保证它不被违反，一次「顺手」重构就会翻成反向顺序，**死锁而不是失败**。
2. **撤销副本 scratch 目录（`~/.codeforge/undo`）刻意不进 Backend。** 它是进程级、跨工作区的。进 Backend 等于给远程后端定义「往我本地 home 目录写文件」的契约。工具结果外置目录（`~/.codeforge/toolout`）属同一类，因此**全部 IO 放在 `pkg/tools` 而不在 `pkg/tools/builtin`**。
3. **`Backend` 不加 `IsInScope` / `CheckScope` 之类的方法。** 加了就等于邀请每个后端自己实现一遍围栏，安全逻辑必然分叉。Backend 只提供 `Realpath`，判断在 Guard。

### 2.3 持久化

- **库文件**：`%USERPROFILE%/.codeforge/data.db`（用户级，跨工作区共享）
- **配置**：`journal_mode(WAL)` + `busy_timeout(5000)` + **`MaxOpenConns(1)`**（单文件库限制写并发）
- **`SaveSession` 是「全删全插」**（`DELETE` + 全量重插），靠 `MaxOpenConns(1)` 兜住并发 —— **若将来放开连接数，跨进程写会丢消息**
- 记忆三层：用户记忆（`save_memory`）、项目级记忆（AGENTS.md 优先于 CLAUDE.md）、技能（`SKILL.md` + frontmatter）

### 2.4 审批文案

HITL 审批条**只显示中文短语，不暴露参数明文**：

```
需要审批：写入文件          （不是：需要审批：write_file（hello.html））
需要审批：执行命令          （不是：需要审批：run_command（start "" "C:\..."））
```

理由：暴露内部工具 id + 明文参数冗长且干扰阅读。工具代号是系统内部名，界面显示中文。
**排查不受影响** —— `AuditEntry` 单独记 `Tool` 字段。

## 三、已知限制

| 限制 | 说明 |
|---|---|
| **跨工作区并发** | 工作区是进程级的，切它会改掉正在跑的会话所看到的工作区。有任务在跑时跨项目切换会被挡并提示 |
| **Termux 降级路径未真机验证** | `termux-storage-get` 失败 → 内置选择器的链路只有单元测试覆盖，未在真机跑过。「继续」与「编辑重发」的前端交互同理（契约断言齐了，真实点击未跑） |
| **无 OS 级沙箱** | 沙箱是应用层路径校验 + 人工审批，**无 seatbelt/landlock/AppContainer 内核级隔离**。这是与 Codex CLI 的最大架构差距，但补它会破坏 `CGO_ENABLED=0` 与单文件静态二进制的产品立意 —— 详见 [对标分析报告](对标分析报告.md) |
| **命令黑名单可绕过** | 正则末尾 `\s*$` 锚定使 `rm -rf / ; echo done`、`rm -r -f /`、`bash -c 'rm -rf /'` 逃逸。默认 `ask` 模式有审批兜底，`auto` 档会全部放行 |
| **`s.cfg` 无锁** | 服务端配置是全仓库唯一无锁的共享可变状态（23 处无锁写 / 92 处读，跨 HTTP 与 WS goroutine）。`pkg/agent` 已有成熟分层锁，但 server 层没继承 |
| **工具元信息靠运行时断言** | `ScopeChecker` / `DiffProvider` / `ReadGate` / `TimeoutPolicy` 漏实现是**静默降级**（漏 `DiffProvider` = 用户盲批）。`delete_file` 与 `create_skill` 确实缺 diff |
| **MCP 只有 tools** | `initialize` 上报空 capabilities，未实现 resources / prompts |

## 四、与对标品的差距

完整分析见 **[对标分析报告](对标分析报告.md)**。

**本项目更好**：上下文在线校准、压缩永不丢历史、大结果无损外置、文件级撤销粒度、
子智能体围栏不可被审批穿透。

**对标品更好**：OS 级安全强制（Codex）、横向扩展点与 hooks（Claude Code）、
执行并行度、可观测性。

**结论**：技术底子比两个对标品都扎实，缺的是「安全强制层」和「横向扩展点」。
**性价比最高的路径不在补大功能，而在把已有能力补齐口径** ——
审计加 session_id、注册期校验元信息、黑名单去锚定、并行调度用上现成的 `SideEffect` 分级。
这些一条依赖都不加。
